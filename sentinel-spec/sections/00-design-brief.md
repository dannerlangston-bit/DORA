# Design brief: thinkorswim UI Regression System (working name: "Sentinel")

This brief is the single source of truth for every section writer. Every decision below is locked unless marked OPEN. Sections must not contradict it. Where a section needs detail the brief does not give, the writer decides, states the decision plainly, and stays consistent with the principles.

## 0. Context and assumptions

- We are the thinkorswim product team (internal). We have: source access, the build pipeline, release-candidate (RC) and per-branch builds, the ticket system (Jira), paperMoney and internal test logins, the ability to install a pinned build with the launcher's auto-update disabled on test rigs, security and compliance contacts, and the option to ask the backend team for deterministic market-data fixtures.
- Platform under test: thinkorswim desktop on Windows 11 (Java/Swing, custom look and feel, bundled JRE, install4j launcher). macOS and Linux are explicit non-goals for phase 1 to 3; the design must not preclude them.
- The problem being solved, in the author's words: a change to one feature (for example Flexible Grid) breaks another (the Active Trader ladder overlaps), user testing of the changed feature does not catch it, and devs hand-screenshot their work to prove it. The system drives the whole product like a user, compares against the build before the change, reports the intended change as evidence and anything else that moved as a suspected regression, and does so for every change, every time, without a human remembering to look.
- A spec cannot remove unknowns about the app's internals. It removes *unhandled* cases. "No gaps" means, operationally:
  1. Every surface in the product is in the Surface Registry, and the registry is validated against the running app on every run; an unregistered surface is a reported outcome, not silence.
  2. Every checkpoint of every run ends in exactly one outcome from a closed taxonomy. There is no silent skip, no silent retry, no silent fallback.
  3. Every claim the system makes about itself ("I can see a missing button") is proven nightly by synthetic-fault canaries.
  4. Every unknown in the plan has a decision branch written down before the spike runs, so no spike result stalls the project.
  5. Every failure mode of the harness, the rig, the network, the account or the model API has a defined handling and a defined place where a human sees it.

## 1. Locked architecture decisions

### 1.1 Run types and the build pair
- The unit of comparison is a **build pair**: candidate build vs base build, both installed from pipeline artifacts, both run on identically fingerprinted rigs in the same data window. Attribution of a diff to a change comes from the build pair, not from AI.
- Run types:
  - **PR run**: candidate = branch build, base = its merge-base main build (or the nearest main ancestor with a build, at most 20 commits back). Scope = dependency-map expansion of the change manifest (surfaces that consume what changed) + the smoke subset of the census. Budget: 45 minutes wall clock, sharded across rigs.
  - **Merge run**: on every merge to main, candidate = new main build, base = previous main build. Scope = full census + all tier-1 flows. Budget: 3 hours.
  - **RC run**: candidate = RC build, base = last released build (lineage baseline). Scope = full census, all flows, size sweeps, soak, Explorer. Budget: 8 hours. Gate: triaged and signed off N business days before GA.
  - **Nightly run**: canaries (mutants), A/A drift check on the current main build, flake statistics refresh, environment fingerprint check. Not a product test.
  - **Calibration run**: same build run 5 times back to back on one rig and once on a second night; produces per-checkpoint, per-region noise floors. Required before any threshold is used, and re-run whenever the environment fingerprint changes.
- Runs happen during the day. The market-closed rule from the original spec is replaced by a **data-mode policy**: each checkpoint declares `data_mode: frozen | masked_live`. Frozen checkpoints run on the deterministic data fixture; masked-live checkpoints use the region registry to freeze, assert-by-rule or mask every region that legitimately changes. Safety does not depend on the clock; it depends on the input gateway and account identity (section 6).

### 1.2 Testing model (the heart of the system)
Five test kinds, all producing checkpoints in the same outcome taxonomy:
1. **Surface census**: visit every surface in the Surface Registry (every tab, sub-tab, gadget, dialog, settings page, context menu that matters, order ticket variant, Active Trader panel, chart with the standard study set, option chain views) in each workspace of the **Workspace Corpus**, capture, diff against the base build, run layout invariants. Baseline-free and flow-free: it does not need to know what the screen should look like, only that it should look like the base build and obey the invariants. This is the part that finds unknown side effects.
2. **Size sweeps**: for every gadget that can live in a Flexible Grid cell or be resized (registry flag `resizable: true`), place it in a grid cell and step width and height through a declared ladder of sizes and splitter positions; capture and run invariants at each step. This is where the ladder overlap is found.
3. **Scripted flows**: YAML flows for interactive states (build an order ticket, open the confirm dialog, add a study, run a scan). Each step may carry assertions evaluated by the Oracle layer. Each checkpoint declares its target window and data mode.
4. **Layout invariants** (baseline-free): no two sibling components' bounds intersect; no component extends outside its parent's bounds; no text clipped at a boundary (OCR word box truncated at a cell edge or with an ellipsis where none existed on base); required labels present; no unexpected scrollbar; minimum legible font height; no placeholder or "Loading" text at capture. Source of bounds: Java Access Bridge (JAB) if the spike shows it exposes them, else OCR word boxes plus template-located controls. Invariant violations are outcomes in their own right and fire on the first run of any new layout.
5. **Oracle checks** (numbers): typed values extracted by OCR on upscaled crops, CSV export and "Copy All" from grids, JAB where available, and the internal/Schwab market-data API; checked against declared expectations in flows, arithmetic invariants (quantity times price equals cost; buying-power effect consistent with position change; put-call relationships for European-style only; strike count and expiration list consistent with the chain header) and the API within a declared tolerance that models paperMoney's delay.
- **Explorer** is a sixth, bounded activity: an agent with the gateway's restricted toolset, its own login and VM snapshot, a step and dollar budget, a deny list, scheduled last in RC runs only, whose findings are recorded as candidate flows and replayed once before being reported.

### 1.3 Coverage model
- **Surface Registry** (git, YAML): every surface with id, path to reach it, hosting primitives it consumes (FlexibleGrid, Docking, ColumnModel, Theme, FontMetrics, ChartEngine, OrderTicketCore, and so on), persona tags, tier (1 = money and orders, 2 = analysis, 3 = everything else), resizable flag, target window kind, data mode, required entitlements.
- **Dependency Map** (git, YAML, derivable from source): primitive -> surfaces that consume it. For PR runs, the orchestrator also runs a static impact step: changed classes and packages from the diff -> dependents -> hosting surfaces, unioned with the manifest's declared surfaces. If the map is missing an edge the static step finds, the run emits `dependency_map_gap` and the edge is proposed as a PR.
- **Workspace Corpus**: tier A canonical workspace (one per persona: active trader, options trader, futures trader, swing trader, beginner default), tier B real power-user workspaces including workspaces saved under the previous release to exercise migration, tier C size-sweep harness workspace. All stored as files in git and dropped into the install's usergui folder on snapshot build.
- **Coverage accounting**: the Reporter prints the surface x persona x entitlement matrix with every cell in one of covered / not_run (reason) / not_registered. "Not run" is never displayed as "passed".
- **Registry validation**: at run start the orchestrator enumerates the app's main menu, tab bar, gadget picker and settings tree by OCR/template and diffs the result against the registry; any new entry yields `unregistered_surface`.

### 1.4 Comparison model
- Pixel diff (pixelmatch-style per-pixel with anti-aliasing tolerance in YIQ) and SSIM on the candidate vs base capture of the same checkpoint, computed at three granularities: whole window (layout shift and translation detection only), named regions from the **Region Registry** (anchored to landmarks, each with its own threshold from the A/A floor), and connected components (binarize, dilate, label, measure area and bounding box).
- **Region Registry**: per checkpoint, every region is one of freeze (the fixture pins it), rule (assert by Oracle, do not pixel-diff), mask (allowed to change, with owner, reason, expiry, created_by human only, budget per critical panel), or diff (default). Masks and regions are offsets from a landmark located by template match each run; a missing landmark is `landmark_missing`, never a blind diff.
- **A/A noise floor**: from calibration runs; a non-zero floor on a frozen checkpoint is a flow or environment bug to fix, not a tolerance to raise.
- **Settle rule**: capture only when 3 consecutive frames at 250 ms are identical outside masks, must-see anchors are present, anti-anchors (Loading, Reconnecting, spinner, empty-grid placeholder) are absent, mouse parked, focus dropped on a neutral control, within a per-checkpoint max wait; otherwise `not_settled`.
- **Classification** of a diff above threshold: `intended` if the checkpoint's surface is in the manifest's declared surfaces and the AI reviewer, given the manifest entry, the base and candidate crops and any mock image, confirms the diff matches the entry; `collateral` if the surface is not declared (highest-priority finding, posted with the primitive it consumes and the manifest entry that touched that primitive); `noise` only if below the A/A floor or matching a noise signature a human approved; `needs_human` otherwise. Invariant violations and assertion failures are never reclassified by the reviewer.
- **AI reviewer**: Claude on the security-approved endpoint with zero-data-retention terms, pinned model id, temperature 0, structured output, inputs = manifest entry, dependency edge, base crop, candidate crop at 1:1, heatmap, flow's expected-screen text, Oracle values; outputs category, confidence, plain-English description, pointer to the region. It never promotes a baseline, never creates masks, never changes an outcome produced by invariants or assertions. It is evaluated against a labeled eval set (target 300 to 500 items, mutants plus A/A pairs plus real diffs double-labeled) and its precision and recall per category are reported per model and prompt version.

### 1.5 Outcome taxonomy (closed set; authoritative copy lives in section 01 and is copied verbatim into the appendix)
Per checkpoint: `identical`, `noise`, `intended`, `collateral`, `needs_human`, `invariant_violation`, `assertion_failed`, `not_settled`, `not_comparable` (fingerprint or landmark mismatch), `landmark_missing`, `env_error` (gate failed before the checkpoint), `harness_error`, `not_run` (with reason: entitlement, budget, scope, quarantine), `unregistered_surface`, `needs_baseline`. Per step: `passed`, `passed_after_retry`, `passed_via_agent_fallback` (with the scripted locator failure recorded as a finding), `failed`, `blocked_by_gateway`. Per run: `complete`, `complete_with_env_errors`, `aborted_safety`, `aborted_budget`, `aborted_harness`. Nothing else exists.

### 1.6 Components
Orchestrator (state machine: provisioned -> launched -> authenticated -> paper_mode_asserted -> settings_attested -> workspace_loaded -> fixture_verified -> canary_flow_passed -> running -> teardown -> reported; every gate verified by an anchor check, every gate failure = env_error with gate name and screenshot), Rig Manager (VM snapshots, pinned build install, fingerprint), Executor (single Input Gateway; locator ladder JAB -> image anchor -> OCR text anchor -> agent; agent-mode restricted toolset; drag, wheel, right-click, double-click, key chord, reset_input_state primitives; secret steps), Capture (per top-level window of the process tree by PID, DWM extended frame bounds, virtual-screen composite, redaction stage), Diff Engine, Invariant Checker, Oracle (OCR, export, JAB, API), Reviewer, Stores (SQLite single writer local disk WAL; content-addressed artifacts; git for registries, flows, masks, corpus), Reporter and Integrations (PR comment, report UI, Jira, Slack), Watchdog (separate process, heartbeat file, process tree tracking, crash artifacts, hs_err_pid collection), Canary Service (mutant injection), Calibration Service, Recorder (flow authoring: global hook plus screenshot per action, emits anchored YAML).

### 1.7 Safety (non-negotiable)
- One **Input Gateway** is the only path to the OS for scripted flows, agent mode and the Explorer. Slow resolution (OCR, template, JAB) happens before an event is emitted; the low-level hook callback consults only in-memory arm/deny state. While a ticket or confirm dialog is the foreground window, Enter, Space, Ctrl+Enter and bound order hotkeys are dropped and logged; any click without a matching one-shot token is dropped.
- **Run-start attestation**: screenshot and OCR of Application Settings (confirmation dialog on, Shift+click send off, Active Trader hotkeys disabled, no order hotkeys bound) and the Auto Send checkbox on every Active Trader panel in the workspace; mismatch = `aborted_safety`.
- **Paper-mode assertion**: account selector text read after login, before every flow, after any re-login; must match a hard-coded allowlist of `D-` accounts; mismatch = kill process tree, `aborted_safety`.
- **Fire drill** nightly: attempt Enter on an open confirm dialog, an Auto Send ladder click, a bound hotkey, Shift+click; pass only if the gateway blocked each and Monitor > Activity and Positions shows no new row.
- **Sends**: by default none. An identity-gated `paper_send_ok` flow class (1 share or 1 contract, far-from-market limit, allowlisted account, fresh frame) is OPEN pending the risk owner; the spec describes both branches. End-of-run Cancel All plus positions-flat check regardless.
- **Kill switch**: file flag plus named pipe; the hook drops all events, the orchestrator kills the process tree, then a fresh scripted login performs verified Cancel All and a diff of Working and Filled against the start snapshot; post-run proof is a report section, not a log line.
- **Explorer boundary**: own login with no verified email or phone (so alerts cannot page anyone), own VM snapshot, deny list (Chat Rooms, Support chat, Share and tos.mx links, Setup, Application Settings, Adjust Account, Logout, account switch, any browser launch), step and dollar budget, scheduled last, never shares a session with scripted flows.
- **Data egress**: redaction stage in Capture (anchored masks over account identifiers and the user's name, OCR-regex sweep for account patterns), only redacted artifacts stored or sent, per-run egress log, security-approved endpoint only; agent mode disabled if computer use is not covered by the agreement (OPEN until security answers).
- **Secrets**: vault reference steps; value typed with recorder paused and capture suspended; logs show `<redacted:login.password>`; login is scripted-only, never agent mode; post-run plaintext scan of artifacts.

### 1.8 Environment
- Rigs: Windows 11 VMs with basic hypervisor console (no RDP-backed console), fixed 1920x1080 at 100% DPI, ClearType state pinned, Java2D pipeline pinned via thinkorswim.vmoptions and recorded per run, time zone America/New_York, en-US layout, toggle keys normalized, display sleep and lock disabled, Windows Update deferred and applied only with a new snapshot and a new calibration. One physical D3D rig in tier B later.
- **Environment fingerprint** computed from live reads at run start (build id from the main window title, JRE release file, vmoptions hash, Windows build, display settings, theme, workspace hash, pipeline) and stored per run; candidate and base must match or every checkpoint is `not_comparable`.
- **State model**: local state (workspace files, usergui folder, vmoptions) restored by snapshot revert; server-side state on the login (positions, working orders, watchlists, alerts, studies, drawings, settings) restored by the fixture reset flow and verified by `verify_account_fixture` at run start; drift = `env_error` not a diff.
- **Logins**: one dedicated paperMoney or test login per rig, named owner, trusted-device MFA exemption or test-backend credential (OPEN which one the platform team grants), credential rotation calendar, re-login flow with its own checkpoints.
- **Popup catalog**: versioned list of title regex plus template plus action (dismiss key, click, wait, relogin, abort, ignore) for everything the app throws on its own; unmatched top-level windows go to the agent with a strict dismiss-only toolset and are logged as `unknown_popup` findings.
- **Data modes**: frozen = deterministic market-data fixture from the backend team (preferred; OPEN) or OnDemand at a pinned, paused timestamp where available on the login; masked_live = paperMoney live-delayed data with the region registry. Quiet windows for anything that still needs them come from an exchange-calendar library in America/New_York, never wall-clock cron.

### 1.9 Reporting and process
- PR comment within the budget with two sections: Intended (declared surfaces, base and candidate crops at 1:1, reviewer confirmation) and Unexpected (collateral diffs, invariant violations, assertion failures ranked by tier, each with the primitive consumed and the manifest entry that touched it, the layout and size that triggered it, and one-click actions: confirm bug, mark intended with ticket, request mask with reason). Plus coverage matrix and run health.
- Decisions persist in SQLite keyed by diff signature (checkpoint id, region, perceptual hash of the anchored crop with Hamming tolerance, category); matching diffs on later runs inherit the decision and appear under "suppressed by decision #id".
- Baseline lifecycle: candidate -> approved -> retired; approval is human-only, per checkpoint or per signature cluster, recorded with approver, build, reason, ticket. The lineage baseline for RC runs is the approved set of the last release.
- Metrics from run one: false-positive rate (noise plus expected over all findings), flake rate (verdict flips between runs of one build or targeted re-runs), time to triage, escape rate (bugs found after release that a registered surface should have shown), coverage percent per tier, canary pass rate. Kill criteria stated.
- Ownership: a named system owner, a triage rotation, a flow owner per surface tier, a maintenance budget in hours per week, an on-call channel for env_error and dead-man alerts.

### 1.10 Reliability of the system itself
- Watchdog separate from the orchestrator; dead-man alert if no run-completed event by deadline.
- Harness, environment and app failures are separate outcome classes and never enter the diff engine.
- Canaries: 20 to 30 deterministic mutants per critical checkpoint (erased button, shifted panel, swapped digit, red/green swap, clipped label, overlapped panels) injected nightly as candidate images; detection rate must stay at 100 percent for money-cell mutants and at the rolling floor for the rest, else the run is `harness_error` and the morning report says the detector is blind.
- Degraded modes: review is asynchronous and idempotent; a run reaches captured-and-diffed and publishes an `unreviewed` report with zero model calls; a reviewer job drains a queue and can use the Batch API; model ids pinned with a deprecation alarm; agent fallback disabled by preflight when the API is unreachable, so flows fail as `failed` not as silent fallbacks.
- Targeted re-runs: a checkpoint whose diff exceeds threshold is re-captured in the same session; identical across re-runs = product change, different = instability, recorded per checkpoint as flake statistics; quarantine is a visible outcome (`not_run: quarantine`).

### 1.11 Unknowns with decision branches (Phase 0 spike, two weeks, on the target rig)
1. JAB exposure: enable via jabswitch on the bundled runtime after checking `java --list-modules` for jdk.accessibility; inspect order ticket, confirm dialog, option chain, Monitor grid, Active Trader ladder. Branch A (bounds and names exposed): invariants and locators use JAB first. Branch B (opaque): invariants use OCR word boxes plus template-located controls; locators are image anchors; both branches are fully specified.
2. Deterministic data fixture: ask the backend team for a replayable market-data mode on the test backend. Branch A (yes): frozen mode uses it. Branch B (no): frozen mode uses OnDemand at a pinned paused timestamp where the login allows, else masked_live for everything with a larger rule set; chart checkpoints then use a fixed historical date range.
3. Login and MFA: Branch A test-backend credential without MFA; Branch B trusted-device exemption with a scripted recovery flow and an owner on call for SMS codes during rig rebuilds.
4. Pinned build install: Branch A pipeline artifact installs with auto-update disabled (expected); Branch B VM snapshots per build with a release-night upgrade run.
5. A/A noise floor on the target rig: Branch A near-zero on frozen checkpoints; Branch B non-zero, treated as flow or environment bugs with a fix list before thresholds are set.
6. Session rule: test empirically whether a second login kicks the first; parallelism equals the number of logins either way.
7. Computer use under the data agreement: Branch A allowed on the approved endpoint; Branch B agent mode and Explorer are deferred, scripted flows plus census carry phase 1.

### 1.12 Phases
- Phase 0 (2 weeks): spike plus rig build plus calibration plus authorization. Exit: all seven branches chosen, fingerprint stable, A/A floor recorded, security ruling in hand.
- Phase 1 (6 weeks): census plus invariants plus build pair plus PR and merge runs plus PR comment plus canaries plus gateway and attestation. Exit: the Flexible Grid / ladder scenario, injected as a mutant and as a real branch change, is caught in a PR run and reported as collateral with the right primitive named.
- Phase 2 (6 weeks): flows with assertions plus Oracle plus region registry plus size sweeps plus reviewer with eval set plus decision persistence plus Jira and Slack plus metrics.
- Phase 3 (6 weeks): RC runs plus lineage baselines plus soak plus Explorer plus tier B workspaces and configs plus recorder plus self-healing proposals.

## 3. Style rules for every section
- Plain, direct, specific. No em-dashes (use commas or periods). No filler, no marketing, no restating the brief's rationale at length. Every mechanism stated so an engineer can build it: inputs, outputs, failure outcome, who sees it.
- Use the outcome names, component names and run type names exactly as in this brief. Do not invent synonyms.
- Where a fact about thinkorswim, paperMoney, Schwab or a library is uncertain, write it as an assumption to verify in Phase 0 and name the branch that handles each answer. Do not present unverified facts as facts. The file final_gaps.json (same folder as this brief's parent) carries the reviewers' verified and unverified notes per gap id; use them.
- Headings: the section's top heading is `## N. Title` as in the table; subsections `### N.M Title`. Tables for schemas, taxonomies and checklists. Code blocks for YAML, JSON, DDL and commands.
- Length: whatever completeness needs; expect 2,500 to 5,000 words per section, more for 02, 04 and 05.
- Cross-reference other sections by number and title only (for example "see 6.3 Fire drill"); the integrator fixes exact numbering.

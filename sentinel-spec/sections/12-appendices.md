## 12. Appendices

Reference material for sections 1 to 11. Where a table copies a brief definition or another section's table, it copies it verbatim and names the source; where it collects vocabulary that other sections introduce, every entry names the section that produces it. Markers: `[verified]` = confirmed by official documentation or the reviewers' notes in final_gaps.json; `[unverified]` = community-reported or inferred, checked on the rig in Phase 0 with the handling branch named in the section cited; `[confirm from source]` = read from the thinkorswim source tree before Phase 1 exit. Nothing marked unverified is used as a gate value until confirmed.

### 12.1 Glossary

Terms from the brief first, then terms the sections introduced. Outcome names are defined in 12.2, invariants in 12.3, reason codes in 12.2.

| Term | Definition |
|---|---|
| A/A floor | Per-checkpoint, per-region diff level from comparing one build with itself in Calibration runs (3.9); thresholds derive from it (factor 2 margin, floor of 4 px). Non-zero on a frozen checkpoint = bug to fix, never a tolerance to raise. |
| Agent mode | Fourth locator rung and the Explorer's driver: the pinned model driving the harness's own tool definitions (`click_named`, `type_fixture`, `press`, `zoom`, `scroll`; Explorer-only `drag_named`), not the computer-use beta tool, only through the Input Gateway (5.6). The pinned items are the model id and the harness toolset schema version. Disabled by the N2 and N5 degraded mode when the model endpoint is unreachable (an agent-only step is then `not_run (reason: model_unavailable)`), or under DR-07 Branch B. |
| Agent rescue | One agent-mode session that completes a scripted step whose rungs 1 to 3 failed; capped at 25 actions and 90 seconds; records a `locator_failure` finding; the checkpoint it leads to is a rescued checkpoint, `needs_human (reason: rescued_capture)`, which never inherits a noise or intended decision (5.5, 9.7). |
| Assumption id spaces | AS-01 to AS-12 are the assumptions of 1.2; PA-01 to PA-14 the planning assumptions of 11.1; SA-01 to SA-07 the storage assumptions of 8.8; A1 to A11 are the attestation rows of 12.6 and nothing else. |
| Anchor / anti-anchor | Template or OCR text that must be present (anchor) or absent (anti-anchor: Loading, Reconnecting, Disconnected, spinner, empty-grid placeholder) before capture (3.5). |
| Anchor lint | Pre-run and CI match of every flow anchor and Region Registry landmark against the latest approved base capture; a miss is a maintenance item, never a checkpoint outcome (11.5). |
| Anchor patch | Proposed flow change built from an agent rescue's final target and 40x20 crop; accepted by the flow owner in re-anchor mode (5.5, 9.6, 11.5). |
| Arm/deny state | In-memory shared-memory state the hook callback consults: `armed`, `deny_all`, `flag_ticket`, one-shot tokens, `move_allow`, `deny_rects`, `blocked_vk`, drop ring (5.4.2). |
| Attestation canary | Nightly check that feeds the attestation reader planted crops with every setting flipped and one unreadable crop; a miss is `harness_error (reason: safety_canary_blind:attestation)` and the morning report says the attestation reader is blind (6.3, 10.3). |
| Base build / candidate build | Older and newer build of a build pair (merge-base main vs branch; previous main vs new main; last release vs RC). |
| Base-capture reuse | A frozen checkpoint's base capture is reused when its reuse key equals the live one: `fingerprint_id`, `epoch_id`, the fixture file's sha256 and the golden account's `seeded_at` (7.9); masked_live checkpoints capture both sides in the same window every run (11.1). |
| Baseline | Approved capture set per checkpoint; lifecycle candidate -> approved -> retired; approval human-only (9.8). |
| Blocked key set | Keys and chords the hook drops while `flag_ticket` is set or unknown: Enter (both), Space, Ctrl+Enter, Shift+Enter, Alt+Enter, Alt+letter, Shift-held clicks, every attested order hotkey (5.4.7). |
| Build pair | Candidate vs base, both from pipeline artifacts, on identically fingerprinted rigs in the same data window (3.1). The unit of comparison. |
| Calibration cause class | Label the Calibration Service puts on a non-zero floor: `caret`, `hover`, `tooltip`, `flash`, `scroll`, `sort`, `live_data`, `settle`, `landmark_jitter`, `unknown`, each with a standard fix (3.9). |
| Calibration run | Per checkpoint, 5 captures back to back on one rig plus 1 on a second night, run in one weekend `all_quiet` window sharded across the pool, rigs 1 to 4; every checkpoint's captures stay on one rig, so the brief's "5 times on one rig" is per checkpoint, not the whole library serially. The Nightly A/A pass pauses that weekend, and the Nightly canaries, fire drill and safety canaries stay on rig 5 (1.6, 3.9, 11.2, 7.13). Yields the A/A floors, keyed by the rendering key of 7.13 (the match fields that affect pixels); required before any threshold is used; re-run on a change of the rendering key, except that floors carry over to a new JRE or `render_probe_hash` when the Nightly A/A pass on it passes (7.13). A rendering key without one diffs at threshold 0 as `needs_human (reason: uncalibrated)`. |
| Emergency calibration | A tier-1-only Calibration run the same night on the pool rigs 1 to 3, sharded as the weekend run is, after a fingerprint change that was not planned as a new snapshot generation; until it passes, above-zero diffs are `needs_human (reason: uncalibrated)` at threshold 0 (11.2, 7.13, 11.10 R21). |
| Canary | Nightly injection of mutants as candidate images through the normal diff and review path (10.3). Also `canary_flow_passed`, the gate that runs one known-good flow first (5.2). |
| Canary result states | Per mutant: `detected`, `missed`, `detector_blind` (a money-cell mutant missed), `detector_degraded` (a class below its rolling floor), `generation_failed` (the mutant could not be generated). The run's canary state, written to `detector_state` in `system_state`, is `generation_failed` only when a critical checkpoint has zero generated mutants or the stage generated none, and otherwise the worse of `detector_blind` and `detector_degraded` when any row has one, else `ok` (10.3); it pages P1 for `detector_blind` and `generation_failed` and puts the banner on every report until the next green Nightly run. They are neither checkpoint outcomes nor reason codes, and the Nightly run's own outcome stays `complete`; it is `aborted_harness (reason: canary_generation_failed)` only when no canary could run at all (10.3, 12.2). |
| Canary detection versus Reviewer recall | Two different numbers. Canary detection of money-cell mutants through the whole deployed pipeline must be 100 percent, else `detector_blind` (10.3, 1.5). The Reviewer's eval-set recall gate on tier-1 items is at least 0.98 per model and prompt version (3.14). Neither substitutes for the other. |
| Census | Visit every Surface Registry surface in every Workspace Corpus workspace that hosts it, capture, diff against base, run invariants (2.4); a persona whose workspace does not host a surface is `not_run (reason: scope)` for that cell by design. Baseline-free and flow-free. |
| Central Store and Run Store | The Run Store is the SQLite WAL database plus `results.jsonl` of one shard on its rig, written only by the Orchestrator; the Central Store on the control host is written only by the Reporter service, which imports every shard at `reported` and owns the API the report UI and one-click actions call. The Watchdog never writes SQLite; it writes a JSONL journal the Orchestrator ingests (8.1, 8.2, 5.13, 10.2). |
| Change manifest | Per-PR list of entries: tickets, declared surfaces, touched primitives, changed paths, expected visual, optional mock image (4.3). The reviewer's only source of intent. |
| Checkpoint | Named capture point in a flow, census visit or sweep step; declares target window and data mode; ends in exactly one outcome. Id format `<kind>/<surface-id>/<qualifier>` with kind `census`, `sweep`, `split` or `flow` (4.1): a census qualifier is the workspace id, a sweep qualifier `<host>/<w>x<h>`, or `<host>/<w>x<h>-asc` for a step of Ladder F's ascending pass, with host `tab`, `sidebar`, `flexgrid`, `detached` or `dialog` (for example `sweep/charts.flexible-grid.active-trader-cell/flexgrid/480x360`), a flow qualifier `<flow-id>/<step-id>` with the full `flow_id` including its `flow.` prefix (for example `flow/dialog.order-confirmation/flow.trade.order-ticket.stock.limit/s07`) (2.5.2, 4.7, 8.3). |
| Classification decision table | The first-match-wins rule list of 3.11 over ten inputs (G gate, H hard checks, B base, D diff level, S stability, M decision memory, T threshold source, P path, X manifest, R reviewer) that gives each checkpoint one outcome in the 1.10 precedence. Row 1a (G `app`) is the app failure `assertion_failed (assertion: app_alive)`; row 9a (H `unreadable`, zero or below-floor diff) is `needs_human (reason: oracle_unreadable)` or `needs_human (reason: bounds_unreadable)`; row 11a (P `rescued`, zero or below-floor diff) is `needs_human (reason: rescued_capture)`; rows 24 to 26 (B `removed`) give `intended` when the Reviewer confirms the removal, `needs_human` with `review_state: pending` while the verdict is pending, `needs_human (reason: reviewer_no_match)` when a declared removal is not confirmed (row 25a), and `collateral` when no manifest entry declares the surface (row 26). When two `needs_human` reasons apply, the first in row order wins and the rest go in `detail` (12.2). |
| Churn calendar | Dated list of option expirations, futures rolls, exchange holidays, earnings and ex-dividend dates for fixture symbols, generated from the exchange calendar and the market-data API; an epoch change on a frozen region triggers baseline re-approval, never scored diffs (7.9, 4.9). |
| Coalesced merge run | When merges outrun capacity, one merge run compares the newest main with the last main that has a completed merge run; manifest is the union and the report names the range (11.2). |
| Collateral | Above-threshold diff on a surface the manifest did not declare, including a UI-touching PR with no manifest (3.11 rows 16 and 17), and a removed surface that no manifest entry declares (row 26); a declared removed surface the Reviewer does not confirm is `needs_human (reason: reviewer_no_match)` (row 25a). A later diff that matches a `confirm_bug` decision keeps its computed outcome and is listed under Known bugs (under Suppressed in a PR comment). Highest-priority finding. |
| Coverage matrix | Surface x persona x entitlement profile; every cell `covered`, `not_run` (reason) or `not_registered` (2.12). |
| Data epoch | Window date, dataset id or OnDemand timestamp, front-month futures contract, nearest option expiration, delayed or real-time state; a fingerprint field, so a pair mismatch is `not_comparable` (3.2, 7.4, 7.9). The 24-hour list hash is not part of `epoch_id`: it is recorded in the fingerprint's record (7.4). Also called fixture epoch. |
| Data mode | `frozen` (deterministic fixture, or OnDemand paused at a pinned timestamp) or `masked_live` (paperMoney delayed data with the Region Registry) (3.2, 7.9). |
| Dead-man alert | Alert for a run that reached `running` (scope manifest uploaded, `run_started` received) and then stopped reporting: no run-completed event by the run's deadline plus grace; the run row is written `aborted_harness (reason: dead_man)` and every checkpoint left without an outcome `harness_error (reason: dead_man)`, the run's abort reason (10.2, 9.10). A run that never reached `running` is never `dead_man`: at its start deadline a PR run is `aborted_budget (reason: pool_saturated)`, a merge run is coalesced into the next merge run, an RC run is decided by the release manager, and a Nightly or Calibration run is `aborted_harness (reason: start_failed)` with the "canaries pending" banner on the next PR comment (11.2, 9.12); a trigger with no `run_started` or `run_queued` within 15 minutes raises the alert as "run not started". |
| Decision | Human triage verdict persisted in SQLite by diff signature; matching diffs on later runs inherit it (9.7, 4.14). A row carries both the UI action (4.14 enum) and the stored verdict (`confirmed_bug`, `intended`, `noise`), and a `source` of `report_ui`, `pr_comment`, `jira_sync` or `explorer_triage`. Status is `active`, `expired`, `superseded` (a newer row replaced it), `reopened` (a fixed signature returned) or `revoked` (a human withdrew it; the revoked fields are set). The lookup returns every active decision within tolerance; conflicting verdicts inherit nothing and are listed as conflicting. Actions, verdicts and inherited outcomes are in 12.2. |
| Detector state | `detector_state` in `system_state`: `ok` or the worst canary result state of the last Nightly run; source of the detector banner (10.3, 9.2). |
| dialog_ok | The slow half's proof, written to shared memory, that its synchronous re-check of the window under the pointer ran for this click; the hook requires it on every button down while `flag_ticket` is set (5.4.2, 5.4.3). |
| Decision records DR-01 to DR-07 | The seven Phase 0 unknowns written as decision records with both branches (11.8): JAB exposure, data fixture, login and MFA, pinned install, A/A floor, session rule, computer use. |
| Deny rects | Inflated bounds of send-like controls currently visible, written by the Window Watcher; the hook drops any button down inside them (5.4.2, 5.4.6). |
| Dependency Map | Git YAML, primitive -> consuming surfaces, derived by bytecode scan with a human overlay (2.10.1, 4.4); drives PR-run scope. Starter in 12.9. |
| dependency_map_gap | Finding (not an outcome) when the static impact step finds an edge the map lacks; edge proposed as a PR (2.10.2). |
| Dialog allowlist | Inside the Order Confirmation dialog only a button whose label is exactly in the pinned set (expected Delete and Edit) may be clicked; elsewhere the slow half refuses labels matching `/send\|submit\|replace\|flatten\|blast\|auto/i` (6.2). |
| Diff signature | Checkpoint id, region id (or 8x8 grid cell), 64-bit pHash of the anchored crop with Hamming tolerance (8 default, 6 for tier 1 and for clustering), category (9.7). |
| Dismiss allowlist | OCR labels the dismiss-only toolset may click on an unmatched popup: OK, Close, Later, Not now, Dismiss, Cancel; never Accept, Agree, Confirm, Send, Yes (7.8). |
| Egress log | Per-run record of every artifact or message that left the rig, with destination, purpose, bytes, redaction version and status (6.10, 8.3). |
| Entitlement | Login capability a surface or flow needs, from the closed vocabulary of 2.2.1 and 4.5: `margin`, `options_L1`, `options_L2`, `options_L3`, `futures`, `forex`, `ira`, `portfolio_margin`, `multi_account`, `paper_send`. Paper send is modeled as an entitlement until the `paper_send_ok` decision; a missing entitlement is `not_run (reason: entitlement)`. |
| Environment fingerprint | Live-read tuple at `provisioned` and `launched`, 22 fields (7.4, 4.12): build id, JRE release, vmoptions hash, jar listing hash, Java2D pipeline, `render_probe_hash`, Windows build, display, ClearType, GPU, OS theme, app theme (color scheme and font size), workspace hash, settings profile hash, time zone, keyboard, data epoch, account, input desktop, rig, harness, run date. Pair mismatch on a match field = `not_comparable (reason: fingerprint_mismatch)` naming the field, and nothing is captured on that shard (12.7 G5); a rendering key (7.13) with no Calibration = `needs_human (reason: uncalibrated)` at threshold 0 and a Calibration run queued (7.13). |
| Eval set | 300 to 500 labeled items (mutants 40 percent, A/A pairs 15, real intended 25, wrong-manifest 10, labeled real diffs 10), 70/30 development and held-out split; gates in 3.14. |
| Explorer | Bounded sixth activity: agent, own login and snapshot, deny list, budgets of 400 actions, 90 minutes, 25 dollars and early stop after 20 consecutive no-change actions; last in RC runs only, on rig 6 from T+6:20 to T+7:50 after the soak reports (1.9, 11.2); budget exhaustion ends the session, never the run; findings replayed once before reporting, and the replayed flow's outcome is `invariant_violation`, `assertion_failed` or `needs_baseline` with the trace, never `needs_human` (2.9, 6.8). `drag_named` is allowed only on splitters and detach handles; order-bubble drags are denied as order paths. The deny list also covers the chart and grid context-menu Buy and Sell items, BUY MKT and SELL MKT, every ladder or Level II bid and ask cell and every order-entry button; three denied attempts end the session, and a ticket or dialog flag set in the session ends it with the `explorer_order_stage` finding while the run continues. With the model endpoint down the session does not start and is `not_run (reason: model_unavailable)` (10.7). |
| Explorer candidate flow | A reproducing Explorer finding written as `flows/quarantine/<finding-id>.yaml` with `class: explorer_candidate`; a human trims and promotes it (2.9, 4.7 L-FLW-14). |
| explorer_order_stage | Finding (not an outcome) raised when the ticket or dialog flag is set in an Explorer session: the gateway drops all input, closes the window through its recovery path (the Escape token), ends the session and counts it toward the per-run trip of ten drops; an S1 routed by the safety routing of 9.10 (P1 to the `aborted_safety` recipients and the Explorer owner, posted to `#sentinel-safety`); the run itself continues. The 30-second open-dialog kill-switch timer applies to scripted flows and agent rescue only (2.9, 5.4.6, 6.8, 4.13). |
| Failure classes | Harness, environment and app failures (10.1); none enters the Diff Engine, the Invariant Checker or the Reviewer. |
| Fire drill | Nightly attempt of every forbidden send path (Enter, Space, Ctrl+Enter on the Order Confirmation dialog; Auto Send ladder click; bound hotkey chords; Shift+click; kill switch end to end); passes only if the gateway blocked each and Monitor > Activity and Positions shows no new row (6.5). An item not blocked with no new row is `harness_error (reason: drill_failed:<item>)`, the flows on that path quarantined; a new order row is run `aborted_safety (reason: drill_order_placed)` and the login is blocked. Both page P1 per the safety routing of 9.10. |
| First-launch rule | A crash or hang signal during the gate sequence of a shard's first launch, before `launched` passes as well as after, is an app failure like any other: `assertion_failed (assertion: app_alive)` with the cause in `detail` on the shard's first checkpoint, finding `app_crash`, one relaunch consumed, never `env_error`; with the relaunch budget spent the run is `aborted_budget (reason: app_restart_budget)` and the unreached checkpoints `not_run (reason: budget)`. A missing main frame with no crash or hang signal at first launch stays `env_error (gate: launched)` (10.1, 10.2, 5.2). |
| Fixture | Declared login, accounts, symbols, positions, watchlists, settings profiles, data mode, epoch and churn calendar (4.9); restored by the fixture reset flow (7.6), verified by `verify_account_fixture`; drift = `env_error (gate: fixture_verified, reason: fixture_drift)`. The base-capture reuse key is `fingerprint_id`, `epoch_id`, the fixture file's sha256 and the golden account's `seeded_at` (7.9). |
| Fixture reset flow | Scripted-only two-stage flow: profile (Application Settings page by page, watchlists, alerts, saved orders, studies, drawings) closing `settings_attested`; account (`verify_account_fixture`, Reset All Balances and Positions, Set Account Cash) closing `fixture_verified` (7.6). |
| flag_ticket (order-stage flag) | Gateway knowledge that an order could be sent from the current screen: OR of window enumeration, the send-control template detector and the flow step's `order_stage: true` declaration; cleared only after two clear polls; `unknown` is treated as set (5.4.6, 6.2). |
| Flake | Verdict flip between runs of one build or between targeted re-runs; tracked per checkpoint in `flake_stats` (10.5). |
| Flow | YAML sequence of header, preconditions, steps, checkpoints, assertions and teardown (4.7); classes standard, login, fixture_reset, teardown, canary, paper_send_ok, explorer_candidate. |
| Gateway drop | Step event for every event the hook dropped or the slow half refused, stored in `step_events` with `gate_decision` `dropped` or `refused`, `gate_reason` (the 5.4.3 or 5.4.4 code, never a coarse class) and `gate_class` `safety` or `integrity`, plus mode, point and keys (5.4.8, 8.3, 4.13). Drop counts are rows with `gate_decision IN ('dropped','refused')`. A safety-reason drop (a blocked key, or a click on a deny rect while `order_stage` is set) quarantines the flow and pages P1; integrity-reason drops (token mismatch, expired token, stale state) get one retry, three in one flow quarantine the flow and ten in one run trip the kill switch. An attempted send on a scripted flow or its agent rescue ends the run `aborted_safety`; in an Explorer session it ends the session and counts toward the ten. |
| GOLDEN and EMPTY | Roles of the two paper accounts on one login: margin account seeded with the golden portfolio by a named human; IRA account kept empty for census, sweeps and most flows (7.6, 4.9). |
| Hook host | The gateway's fast half: a separate stdlib-only Python process holding `WH_MOUSE_LL` and `WH_KEYBOARD_LL`, consulting only the seqlock shared memory, failing closed to `deny_all` when the Orchestrator dies (5.4.2, 5.4.4). One of the three harness processes with the Orchestrator and the Watchdog. |
| Identity canary | Nightly dry run of the paper-mode assertion against a synthetic live-format selector and a `D-` id not on the allowlist; both must abort (6.4). A miss is `harness_error (reason: safety_canary_blind:identity)` with the dependent flows `not_run (reason: quarantine)`; the run stays `complete` (4.13, 10.3). |
| Identity fields | The account number and the account holder (login display) name wherever they appear: always redacted in Capture (3.6, 6.10), excluded from the mask budget, never a region, never diffed and not money cells; proven nightly by the redaction canary and the redaction mutant M19. A miss is `harness_error (reason: safety_canary_blind:redaction)` (3.8, 4.8, 12.5). |
| Input Gateway | Only path to the OS for flows, agent mode and Explorer. Slow half resolves and tokens before emission; the hook consults only arm/deny state (5.4, 6.2). |
| Intended | Declared surface and the reviewer confirms the diff matches the manifest entry at or above the 0.80 routing threshold (3.11 row 20). |
| Invariant | Baseline-free rule about bounds, text, labels and colors (12.3). Violations are outcomes and are never reclassified; a violation is re-captured once to confirm it persists (3.10). An enabled invariant that fires on a Nightly A/A pair is `harness_error (reason: invariant_on_aa)` (2.7). |
| Kill switch | File flag (controller command over the hypervisor guest channel) plus named pipe, both proven by preflight H5, and automatic trip-wires: hook drops all events, process tree killed, fresh scripted login does verified Cancel All and diffs Working and Filled against the start snapshot (6.6). |
| Known bugs | Merge and RC report section listing findings that inherit an open `confirm_bug` decision, with ticket status and age (9.4); a PR comment has no such block and lists them under Suppressed (9.2). |
| Ladder S and Ladder F | Size-sweep ladders (2.5.2). S: widths {320, 480, 640, 960} by heights {360, 480, 720}, 12 steps, PR and merge runs. F: 6x6 grid {320, 400, 480, 640, 800, 960} by {300, 360, 420, 480, 600, 720}, four corners with MAXW and MAXH (the `work_area` of the pinned display configuration in `configs/allowed.yaml`), corpus sizes (from `corpus/measured_sizes.yaml`; `not_run (reason: scope)` until it exists) and an ascending pass whose step ids end in `-asc`, about 46 steps plus corpus, RC runs (2.5.2). Both contain 480x360. Splitter sets: short {0.15, 0.50, 0.85}, full {0.00, 0.15, 0.30, 0.50, 0.70, 0.85, 1.00}. |
| Landmark | Template-located feature from which regions, masks and redactions are offsets (3.7). Missing = `landmark_missing`, never a blind diff. |
| Lineage baseline | Approved capture set of the last released build on the same release channel; the base for RC runs; re-captured when its stored fingerprint differs from the live one (3.1, 9.8). |
| Locator ladder | JAB -> image anchor -> OCR text anchor -> agent; one scripted retry after `reset_input_state`; rung logged per step (5.5). |
| locator_failure | Finding, never an outcome, recorded when every scripted rung of a step failed, whether the agent rescued the step (`passed_via_agent_fallback`) or it ended `failed`; carries every rung's result, the pre-attempt screenshot, the agent trace, the final target, the 40x20 crop and the proposed anchor patch (5.5, 1.10, 4.13). |
| Lockstep | masked_live checkpoints run on two identically fingerprinted rigs within 60 s of each other; a larger slip re-queues the pair once and a second slip is `not_run (reason: budget)`, counted as `lockstep_slip` in run health (a counter, never a finding); if only one rig is free they are `not_run (reason: budget)` (3.1, 1.6). |
| Mask | Region allowed to change, with owner, reason, ticket, expiry (default 30 days), human creator, per-critical-panel budget over masks plus non-identity redaction boxes: Order Confirmation 10 percent, order entry 10, Position Statement 10, Account Info 5, money cells 0 (3.8, 4.8). The report UI refuses a mask request that would exceed a budget and the finding stays open until `confirm_bug` or `mark_intended`; raising a budget is a system-owner PR to `sentinel-config` (9.6). |
| mask_budget_exceeded | Run-time breach of a mask budget: a landmark move or geometry change pushes a panel's masked plus non-identity redacted share over its budget, or a mask or redaction box lands on a money cell; the checkpoint is `harness_error (reason: mask_budget_exceeded)` with the panel and share in `detail`, and a `mask_budget_exceeded` finding goes to on-call and the mask owner (3.8, 4.8, 4.13). One spelling everywhere. |
| Merge run | Every merge to main; new main vs previous main; full census plus all tier-1 flows; 3 hours; 4 pool rigs (1.6, 11.2). |
| Missed in PR run and missed by static impact; `missed_in_pr_run` | Merge-run report labels (1.8, 9.4), both stored as the finding kind `missed_in_pr_run`. "Missed in PR run": a merge-run finding on a surface its PR run had in scope but did not report; it opens a harness task. "Missed by static impact": a finding on a surface the candidate's dependency index reaches from a class a merged PR changed, whose PR run had the surface `not_run (reason: scope)`; it is the same kind with `detail: static_impact` and opens a harness task for the system owner (1.10, 4.13). |
| model_unavailable | `not_run` reason for an Explorer session or an agent-only step skipped because the model endpoint is down (the N2 and N5 degraded mode); counted in run health for the harness on-call and in the weekly coverage review, and printed in the RC report as "Explorer: not run, model endpoint unavailable" (10.7, 9.12). |
| Money cell | A region with a `money_role` (4.8), one closed list: `qty`, `price`, `bp_effect` (Buying Power Effect), `max_loss`, `send`, `cancel` and `delete`, on the Order Confirmation dialog and the order ticket (panels `order_confirmation` and `order_ticket`; the ticket's Confirm and Send button is `send`); `money_cell` is true exactly when `money_role` is set (L-RGN-08). A tier-1 money cell is a money cell on a tier-1 checkpoint; nothing promotes a lower-tier item (9.2). Always pixel-diffed and rule-asserted: a `diff` (or `freeze`) region at a zero floor, never `rule` only and never `mask`, asserted on a flow checkpoint by an assertion naming the region and on a census or sweep checkpoint by a `rule` region of its regions file over the same cell, since rule fields sit only on `rule` regions and census and sweep checkpoints run every `rule` region of their regions file (L-RGN-03, L-RGN-04); 0 percent mask budget; 100 percent canary detection (3.8, 4.8, 10.3). The list is closed: the ladder price column, P/L, balances and the BUY and SELL labels are tier-1 regions, not money cells, and their mutants are non-money, counting toward `detector_degraded` (12.5). ### 12.2 Outcome taxonomy

This subsection mirrors three authoritative sources and adds nothing to them: the precedence paragraph and the outcome tables are a verbatim copy of 1.10 Outcome taxonomy (authoritative); the reason table and the finding table are verbatim copies of the reason and finding vocabularies of 4.13 Outcome record, which `taxonomy.yaml`, the `outcome_reasons` seed and the `findings.kind` CHECK of 8.3 carry; and the action table is a verbatim copy of 4.14 Decision record. Verbatim from brief 1.5:

> Per checkpoint: `identical`, `noise`, `intended`, `collateral`, `needs_human`, `invariant_violation`, `assertion_failed`, `not_settled`, `not_comparable` (fingerprint or landmark mismatch), `landmark_missing`, `env_error` (gate failed before the checkpoint), `harness_error`, `not_run` (with reason: entitlement, budget, scope, quarantine), `unregistered_surface`, `needs_baseline`. Verbatim from 1.10:

Precedence. A checkpoint can produce several results (an invariant fires and the pixel diff is also above threshold). It ends in exactly one outcome, the first that applies in this order: `env_error`, app failure (`assertion_failed (assertion: app_alive)`), `harness_error`, `not_run`, `not_comparable`, `not_settled`, `landmark_missing`, `invariant_violation`, `assertion_failed` (every other assertion), `needs_baseline`, `collateral`, `needs_human`, `intended`, `noise`, `identical`. Environment outranks the app and the harness because a hang during a network drop is an environment fact, and an app failure outranks the harness because an exception raised while handling an app failure is evidence of that failure, not a harness fault (10.1). Lower results that also applied stay on the finding record as evidence (a `collateral` classification on an `invariant_violation` finding) but are not outcomes. `unregistered_surface` is a checkpoint of its own created by registry validation and never competes. The rule list in 3.11 Classification decision table implements this order. One refinement inside that list: a region with no calibrated floor cannot be said to be above a threshold, so `needs_human (reason: uncalibrated)` is decided before `collateral` (3.11 row 15) and is ranked with `collateral` in the report.
